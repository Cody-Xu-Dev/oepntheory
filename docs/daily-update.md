# 每日维护流程

每天 Asia/Shanghai 09:00，由本聊天定时任务执行。首次定时运行从初始化日前 7 天检索；其后从最近完整运行 coverage_to 回溯 48 小时，重查所有未完成窗口。若平台有索引延迟，每周额外回溯 30 天（首个周日运行）。时间未知的结果不得当成当天发布。

1. 从 `Cody-Xu-Dev/opentheory` 的 main 读取最新数据、文档和查询配置。只维护这个仓库，禁止复制父目录资料。
2. 对 `config/watchlist.json` 中四个主题的每个查询执行联网搜索，检查已有来源页面是否有实质修订。原作者/平台材料优先，二次研究补充；B 站、X、知乎、微博、抖音等可访问的公开页面可纳入，受限页面记失败或元数据。
3. 执行发现查询，记录新命名与衍生理论；不按健康、金融或人际建议来背书其内容。搜索词可以扩展，但不能省略既有主题。搜索排序不是可靠发布时间。
4. 打开资料，核对作者、日期、正文。写原创摘要，保留原网址；文字稿标明二次转录，未核对视频不写成原视频已验证。无法核读的线索不支持实质观点。
5. 去重并写来源、条目与事件。观点冲突保留版本，不抹平。旧资料的新发现归 source_added，不写成作者当天更新。新理论先 candidate，足够证据再 tracked。
6. 每天写 Run；覆盖窗口与实际搜索能力匹配。缺失来源、网络故障、正文不通要记入 failures，status=partial/failed。若没有新增，event_ids=[]，照样保存日志。不要假造成功结果。
7. 执行 `python scripts/catalog.py validate`、`build`、`check`、`python -m unittest discover -s tests -v`。每次 build 会按数据重建阅读层，同日多个 run 都保留。
8. 将新增数据与生成页批量提交到 GitHub main，消息 `docs: daily theory digest YYYY-MM-DD`。必须使用当前远端 SHA 的乐观并发检查；失败时不强推，重新整合；日志内容审核通过前不要发布。
9. 校验远端提交及生成页确已更新。有实质内容变化时通知并附摘要链接；无内容变化保持安静；发布失败、访问持续失败或需要用户操作时明确通知。不能把本地完成当成远端已发布。

## 定时任务与 CI 的边界

真正的公开搜索、核读、判断和提交由 Codex 定时任务完成；需要本机开机、应用运行和 GitHub 连接可用。GitHub Actions 的 `validate.yml` 只验证已经提交的数据，不提供联网聚合。当前不配置另一个重复的每日采集任务，不要求用户提供付费模型 API key。

## 手动修订

修正内容时更新当前 theory，同时新增 correction event、必要的 source version 和手动 Run。旧事件/来源不要删除或悄悄改写。时区变更、来源停更、排除规则变更在配置和此文档同步维护。
